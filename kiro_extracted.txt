27-## SECTION 1: SWING HIGH / SWING LOW DETECTION
28-
29-### 1.1 Overview
30-
31-A "swing" is a local extremum (peak or trough) in price data. The bot must identify these points on 1H and 4H candle data to establish the "dealing range" for Fibonacci calculations.
32-
33-### 1.2 Candle Data Structure
34-
35-Every candle at index `i` has the following properties:
36-
37-```
38-Candle[i] = {
39- Open: O[i], // Opening price (body boundary)
40- High: H[i], // Highest price reached (wick tip)
41- Low: L[i], // Lowest price reached (wick tip)
42- Close: C[i], // Closing price (body boundary)
43- Time: T[i] // Candle open timestamp
44-}
45-```
46-
47-**Body boundaries:**
48-```
49-Body_High[i] = max(O[i], C[i])
50-Body_Low[i] = min(O[i], C[i])
51-```
52-
53-### 1.3 Candle Indexing Convention
54-
55-```
56-Index 0 = OLDEST candle in dataset (leftmost)
57-Index N = NEWEST candle (rightmost, most recent)
58-
59-For a candle at index i:
60- Left candles: i-1, i-2, i-3, ... (older)
61- Right candles: i+1, i+2, i+3, ... (newer)
62-```
63-
64-### 1.4 Configuration Parameter: Lookback (L)
65-
66-```
67-L = number of candles to compare on EACH side
68-DEFAULT: L = 3
69-
70-This means:
71-- Compare 3 candles to the LEFT
72-- Compare 3 candles to the RIGHT
73-- Total window = 2L + 1 = 7 candles
74-```
75-
76-**Rationale:** L=3 provides a balance between noise filtering and responsiveness on 1H/4H charts. L=1 would produce too many false swings; L=5 would miss relevant shorter-term structures.
77-
78-
79-
80-### 1.5 Swing High – Mathematical Definition
81-
82-A candle at index `i` is a **Swing High** if and only if ALL of the following conditions are TRUE:
83-
84-```
85-CONDITION SET (Swing High at index i):
86-
87- FOR ALL j WHERE j ∈ {1, 2, 3, ..., L}:
88- H[i] > H[i - j] // Higher than ALL L candles to the left
89- H[i] > H[i + j] // Higher than ALL L candles to the right
90-
91- ADDITIONALLY:
92- i >= L // Enough candles exist on the left
93- i <= N - L // Enough candles exist on the right (confirmation)
94-```
95-
96-**Formal notation:**
97-```
98-SwingHigh(i) = TRUE iff ∀ j ∈ [1, L]: H[i] > H[i-j] AND H[i] > H[i+j]
99-```
100-
101-**The swing high VALUE is:** `H[i]` (the wick high, NOT the body high)
102-
103-### 1.6 Swing Low – Mathematical Definition
104-
105-A candle at index `i` is a **Swing Low** if and only if ALL of the following conditions are TRUE:
106-
107-```
108-CONDITION SET (Swing Low at index i):
109-
110- FOR ALL j WHERE j ∈ {1, 2, 3, ..., L}:
111- L[i] < L[i - j] // Lower than ALL L candles to the left
112- L[i] < L[i + j] // Lower than ALL L candles to the right
113-
114- ADDITIONALLY:
115- i >= L // Enough candles exist on the left
116- i <= N - L // Enough candles exist on the right (confirmation)
117-```
118-
119-**Formal notation:**
120-```
121-SwingLow(i) = TRUE iff ∀ j ∈ [1, L]: L[i] < L[i-j] AND L[i] < L[i+j]
122-```
123-
124-**The swing low VALUE is:** `L[i]` (the wick low, NOT the body low)
125-

128-### 1.7 Measurement Basis: WICK ONLY
129-
130-**CRITICAL RULE:** Swing detection uses ONLY wick extremes (H[i] and L[i]), NEVER candle body.
131-
132-```
133-Swing High price = H[i] (NOT max(O[i], C[i]))
134-Swing Low price = L[i] (NOT min(O[i], C[i]))
135-```
136-
137-**Reason:** Wicks represent the true extreme of institutional activity at that moment.
138-
139-### 1.8 Confirmation Requirement
140-
141-A swing is ONLY confirmed after `L` candles have formed to its right.
142-
143-```
144-Swing High at index i is CONFIRMED when candle at index (i + L) has CLOSED.
145-Swing Low at index i is CONFIRMED when candle at index (i + L) has CLOSED.
146-```
147-
148-**Implication:** The bot cannot identify a swing in real-time on the current forming candle. It must wait for L candles to close after the suspected swing candle.
149-
150-**Example (L=3):**
151-```
152-Candle index: ... 10, 11, 12, 13, 14, 15 ...
153- ^
154- Suspected swing at i=12
155-
156-Confirmation: Candle 15 must CLOSE before swing at i=12 is confirmed.
157-The bot can only use this swing after T[15] + candle_duration.
158-```

160-### 1.9 Equal Highs / Equal Lows Handling
161-
162-**Problem:** What if `H[i] == H[i-1]` or `H[i] == H[i+1]`?
163-
164-**Rule: STRICT INEQUALITY is required.**
165-
166-```
167-If H[i] == H[i-j] for ANY j ∈ [1, L]: SwingHigh(i) = FALSE
168-If H[i] == H[i+j] for ANY j ∈ [1, L]: SwingHigh(i) = FALSE
169-
170-If L[i] == L[i-j] for ANY j ∈ [1, L]: SwingLow(i) = FALSE
171-If L[i] == L[i+j] for ANY j ∈ [1, L]: SwingLow(i) = FALSE
172-```
173-
174-**Tolerance Exception:**
175-```
176-EQUAL_TOLERANCE = 0.00001 (for forex pairs with 5 decimal places)
177- = 0.1 (for indices/metals with 1 decimal place)
178-
179-"Equal" means: |H[i] - H[j]| <= EQUAL_TOLERANCE
180-
181-If prices are "equal" within tolerance → swing is INVALID at that index.
182-```
183-
184-**Rationale:** Equal highs/lows represent liquidity pools (stop hunts), not true swing extremes. The bot should NOT use them as swing anchors for Fibonacci.
185-

188-### 1.10 Minimum Spacing Between Swings
189-
190-**Problem:** Two swing highs forming on adjacent candles would produce an unreliable dealing range.
191-
192-**Rule:**
193-```
194-MIN_SWING_DISTANCE = 2 * L + 1 = 7 candles (when L=3)
195-
196-If SwingHigh(i) = TRUE and SwingHigh(j) = TRUE:
197- If |i - j| < MIN_SWING_DISTANCE:
198- KEEP the swing with the HIGHER H[] value
199- DISCARD the other
200-
201-If SwingLow(i) = TRUE and SwingLow(j) = TRUE:
202- If |i - j| < MIN_SWING_DISTANCE:
203- KEEP the swing with the LOWER L[] value
204- DISCARD the other
205-```
206-
207-**Example:**
208-```
209-SwingHigh at i=10: H[10] = 1.2500
210-SwingHigh at i=13: H[13] = 1.2520
211-
212-Distance = |13-10| = 3 < 7 (MIN_SWING_DISTANCE)
213-
214-KEEP i=13 (H=1.2520 is higher)
215-DISCARD i=10
216-```

218-### 1.11 Nested Swings
219-
220-**Definition:** A nested swing is a minor swing that forms INSIDE the range of a larger swing structure.
221-
222-```
223-Given SwingHigh(a) and SwingLow(b) form a dealing range:
224- Range_High = H[a]
225- Range_Low = L[b]
226-
227-A nested swing at index c is one where:
228- L[b] < H[c] < H[a] (for nested swing high)
229- L[b] < L[c] < H[a] (for nested swing low)
230-```
231-
232-**Rule:** The bot should use the MOST RECENT valid swing pair (high + low) that satisfies all validation criteria. Nested swings within a larger range are IGNORED unless they form a new validated pair themselves.
233-
234-### 1.12 Multiple Swing Highs / Overlapping Swings
235-
236-**Scenario:** Multiple valid swing highs exist in the lookback window.
237-
238-**Selection Rule:**
239-```
240-LOOKBACK_WINDOW = 100 candles (configurable)
241-
242-1. Scan from index (N - LOOKBACK_WINDOW) to index (N - L)
243-2. Collect ALL valid swing highs into list: SH_list[]
244-3. Collect ALL valid swing lows into list: SL_list[]
245-4. Apply minimum spacing filter (Section 1.10)
246-5. Select the MOST RECENT swing high from filtered SH_list
247-6. Select the MOST RECENT swing low from filtered SL_list
248-7. The pair (most_recent_SH, most_recent_SL) defines the dealing range
249-
250-CONSTRAINT: The selected swing high and swing low must form a LOGICAL pair:
251- - Swing High index ≠ Swing Low index
252- - There must be at least 5 candles between them: |SH_index - SL_index| >= 5
253-```

257-### 1.13 Scanning Algorithm – Pseudo Code
258-
259-```python
260-def detect_swings(candles, L=3, lookback_window=100):
261- """
262- Scans candle array and returns validated swing highs and swing lows.
263-
264- Parameters:
265- candles: array of Candle objects with .High, .Low, .Open, .Close, .Time
266- L: number of candles to compare on each side (default=3)
267- lookback_window: how many candles back to scan (default=100)
268-
269- Returns:
270- swing_highs: list of {index, price, time}
271- swing_lows: list of {index, price, time}
272- """
273-
274- N = len(candles) - 1 # Last candle index
275- start = max(L, N - lookback_window)
276- end = N - L # Cannot confirm swings in last L candles
277-
278- raw_swing_highs = []
279- raw_swing_lows = []
280-
281- # STEP 1: Identify all raw swing points
282- for i in range(start, end + 1):
283-
284- # --- Check Swing High ---
285- is_swing_high = True
286- for j in range(1, L + 1):
287- if candles[i].High <= candles[i - j].High:
288- is_swing_high = False
289- break
290- if candles[i].High <= candles[i + j].High:
291- is_swing_high = False
292- break
293-
294- if is_swing_high:
295- raw_swing_highs.append({
296- 'index': i,
297- 'price': candles[i].High,
298- 'time': candles[i].Time
299- })
300-
301- # --- Check Swing Low ---
302- is_swing_low = True
303- for j in range(1, L + 1):
304- if candles[i].Low >= candles[i - j].Low:
305- is_swing_low = False
306- break
307- if candles[i].Low >= candles[i + j].Low:
308- is_swing_low = False
309- break
310-
311- if is_swing_low:
312- raw_swing_lows.append({
313- 'index': i,
314- 'price': candles[i].Low,
315- 'time': candles[i].Time
316- })
317-
318- # STEP 2: Apply minimum spacing filter
319- swing_highs = filter_min_spacing(raw_swing_highs, MIN_SWING_DISTANCE, 'high')
320- swing_lows = filter_min_spacing(raw_swing_lows, MIN_SWING_DISTANCE, 'low')
321-
322- return swing_highs, swing_lows
323-
324-
325-def filter_min_spacing(swings, min_distance, swing_type):
326- """
327- Remove swings that are too close together.
328- Keep the more extreme one (higher for highs, lower for lows).
329- """
330- if len(swings) <= 1:
331- return swings
332-
333- filtered = [swings[0]]
334-
335- for i in range(1, len(swings)):
336- last = filtered[-1]
337- current = swings[i]
338- distance = abs(current['index'] - last['index'])
339-
340- if distance < min_distance:
341- # Too close - keep the more extreme
342- if swing_type == 'high':
343- if current['price'] > last['price']:
344- filtered[-1] = current # Replace with higher
345- else: # low
346- if current['price'] < last['price']:
347- filtered[-1] = current # Replace with lower
348- else:
349- filtered.append(current)
350-
351- return filtered
352-```

473-## SECTION 2: FIBONACCI PREMIUM / DISCOUNT LOGIC
474-
475-### 2.1 Overview
476-
477-Fibonacci retracement is a mathematical tool used to divide a price range into proportional zones. The bot uses it to classify the dealing range (between a swing high and swing low) into **Premium Zone** (expensive / sell area) and **Discount Zone** (cheap / buy area).
478-
479-**Key Concept:** Institutions accumulate positions in discount zones (cheap) and distribute in premium zones (expensive). The bot identifies which zone an order block sits in to determine trade direction.
480-
481-### 2.2 Core Definitions
482-
483-```
484-Dealing Range = The price distance between a validated Swing High and Swing Low
485-
486-Anchor A = Starting point of Fibonacci measurement
487-Anchor B = Ending point of Fibonacci measurement
488-
489-Equilibrium = The exact 50% midpoint of the dealing range
490-Premium Zone = Price area ABOVE equilibrium (expensive)
491-Discount Zone = Price area BELOW equilibrium (cheap)
492-```
493-
494-### 2.3 Fibonacci Anchor Points
495-
496-**CRITICAL: Fibonacci is ALWAYS drawn from wick-to-wick (not body-to-body).**
497-
498-#### For BEARISH setups (looking for sells):
499-```
500-Anchor A = Swing High = H[swing_high_index] (the wick high)
501-Anchor B = Swing Low = L[swing_low_index] (the wick low)
502-
503-Direction: TOP → BOTTOM
504-Fibonacci 0% = Swing High (Anchor A)
505-Fibonacci 100% = Swing Low (Anchor B)
506-```
507-
508-#### For BULLISH setups (looking for buys):
509-```
510-Anchor A = Swing Low = L[swing_low_index] (the wick low)
511-Anchor B = Swing High = H[swing_high_index] (the wick high)
512-
513-Direction: BOTTOM → TOP
514-Fibonacci 0% = Swing Low (Anchor A)
515-Fibonacci 100% = Swing High (Anchor B)
516-```
517-
518-### 2.4 Fibonacci Level Calculation Formula
519-

935-
936-### 3.1 Overview
937-
938-This is a **custom invalidation rule** that prevents the bot from using stale or already-reacted-to swings. The core principle:
939-
940-> **A swing becomes INVALID if price has already touched or crossed the 50% equilibrium level AFTER the swing was confirmed.**
941-
942-**Rationale:** Once price reaches the 50% equilibrium of a dealing range, institutions have already partially filled their orders. The original swing structure has been "used up" and should not be relied upon for new entries.
943-
944-### 3.2 Core Rule – Formal Definition
945-
946-```
947-Given:
948- - SwingHigh confirmed at index SH_idx, price = H[SH_idx]
949- - SwingLow confirmed at index SL_idx, price = L[SL_idx]
950- - Confirmation candle index = max(SH_idx, SL_idx) + L
951- - Equilibrium = (H[SH_idx] + L[SL_idx]) / 2
952-
953-The swing pair is VALID if and only if:
954- FOR ALL candles k WHERE k > Confirmation_Index AND k <= Current_Index:
955- NO candle has "touched" the Equilibrium level.
956-
957-If ANY candle touches equilibrium after confirmation:
958- The swing pair becomes PERMANENTLY INVALID.
959- Bot must discard it and scan for a new swing pair.

963-

966-**RULE: A candle "touches" the 50% level if its WICK passes through or reaches the equilibrium price.**
967-

1109- candles: full candle array
1110- sh_index: index of the swing high candle
1111- sl_index: index of the swing low candle
1112- L: lookback parameter (for confirmation calculation)
1113-
1114- Returns:
1115- {
1116- 'valid': bool,
1117- 'invalidated_at': index or None,
1118- 'equilibrium': float
1119- }
1120- """
1121- TOUCH_TOLERANCE = 0.0002 # Configure per instrument
1122-
1123- # Calculate equilibrium
1124- swing_high_price = candles[sh_index].High
1125- swing_low_price = candles[sl_index].Low
1126- equilibrium = (swing_high_price + swing_low_price) / 2
1127-
1128- # Determine confirmation index
1129- confirmation_index = max(sh_index, sl_index) + L
1130-
1131- # Current candle index
1132- current_index = len(candles) - 1
1133-
1134- # Check all candles AFTER confirmation
1135- for k in range(confirmation_index + 1, current_index + 1):
1136-
1137- # Standard touch check
1138- candle_low = candles[k].Low
1139- candle_high = candles[k].High
1140-
1141- if (candle_low - TOUCH_TOLERANCE) <= equilibrium <= (candle_high + TOUCH_TOLERANCE):
1142- return {
1143- 'valid': False,
1144- 'invalidated_at': k,
1145- 'equilibrium': equilibrium
1146- }
1147-
1148- # Gap check (if k > confirmation_index + 1)
1149- if k > confirmation_index + 1:
1150- prev_high = candles[k-1].High
1151- prev_low = candles[k-1].Low
1152-
1153- # Bullish gap over equilibrium
1154- if prev_high < equilibrium and candle_low > equilibrium:
1155- return {
1156- 'valid': False,
1157- 'invalidated_at': k,
1158- 'equilibrium': equilibrium
1159- }
1160-
1161- # Bearish gap over equilibrium
1162- if prev_low > equilibrium and candle_high < equilibrium:
1163- return {
1164- 'valid': False,
1165- 'invalidated_at': k,
1166- 'equilibrium': equilibrium
1167- }
1168-
1169- # No touch found - swing is still valid
1170- return {
1171- 'valid': True,
1172- 'invalidated_at': None,
1173- 'equilibrium': equilibrium
1174- }
1175-```

1310-## SECTION 4: UNMITIGATED ORDER BLOCK DETECTION
1311-
1312-### 4.1 Overview
1313-
1314-An **Order Block (OB)** is a specific candle that represents institutional activity — a large order placement before a significant price move. The bot must:
1315-1. Identify Order Blocks (three types)
1316-2. Define their exact boundaries
1317-3. Track whether they have been "mitigated" (revisited) or remain "unmitigated" (untouched)
1318-
1319-Only **UNMITIGATED** Order Blocks are valid for trade entries.
1320-
1321-### 4.2 Order Block Types
1322-
1323-The strategy defines THREE types of order blocks:
1324-
1325-```
1326-1. Normal Order Block — Last opposite candle before impulsive move
1327-2. Mitigation Block — Revisited imbalance zone used before continuation
1328-3. Breaker Block — Failed order block that flips into support/resistance
1329-```
1330-
1331----
1332-
1333-### 4.3 TYPE 1: Normal Order Block – Definition
1334-
1335-#### 4.3.1 Bullish Normal Order Block
1336-
1337-**Definition:** The last BEARISH candle before a strong bullish expansion that breaks structure upward.
1338-
1339-```
1340-CONDITIONS for Bullish Normal OB at candle index i:
1341-
1342-1. Candle[i] is BEARISH:
1343- Close[i] < Open[i]
1344-
1345-2. Candle[i+1] (or subsequent candles) create BULLISH DISPLACEMENT:
1346- The move from candle[i] to the next swing creates a strong upward move.
1347-
1348- DISPLACEMENT CONDITION:
1349- Let displacement_candles = candles from index (i+1) to (i+D) where D = displacement window
1350-
1351- Total_Bullish_Move = max(High[i+1..i+D]) - Low[i]
1352-
1353- Displacement is VALID if:
1354- Total_Bullish_Move >= 2 × ATR(14)
1355-
1356- WHERE ATR(14) = Average True Range of the last 14 candles before index i
1357-
1358- ATR(14) calculation:
1359- TR[k] = max(H[k] - L[k], |H[k] - C[k-1]|, |L[k] - C[k-1]|)
1360- ATR(14) = (1/14) × Σ TR[k] for k = (i-14) to (i-1)
1361-
1362-3. STRUCTURE BREAK:
1363- After the bullish displacement, price must break above the most recent swing high
1364- that existed BEFORE candle[i].
1365-
1366- Let previous_swing_high = most recent SwingHigh price before index i
1367-
1368- Structure_Break = TRUE if:
1369- max(High[i+1..i+D]) > previous_swing_high
1370-
1371-4. DISPLACEMENT WINDOW:
1372- D = 5 candles (default)
1373- The bullish move must occur within 5 candles after the OB candle.
1374-```
1375-
1376-**The Bullish Normal OB candle = candle[i]**
1377-
1378-

1380-#### 4.3.2 Bearish Normal Order Block
1381-
1382-**Definition:** The last BULLISH candle before a strong bearish expansion that breaks structure downward.
1383-
1384-```
1385-CONDITIONS for Bearish Normal OB at candle index i:
1386-
1387-1. Candle[i] is BULLISH:
1388- Close[i] > Open[i]
1389-
1390-2. BEARISH DISPLACEMENT:
1391- Total_Bearish_Move = High[i] - min(Low[i+1..i+D])
1392-
1393- Displacement is VALID if:
1394- Total_Bearish_Move >= 2 × ATR(14)
1395-
1396-3. STRUCTURE BREAK:
1397- Let previous_swing_low = most recent SwingLow price before index i
1398-
1399- Structure_Break = TRUE if:
1400- min(Low[i+1..i+D]) < previous_swing_low
1401-
1402-4. DISPLACEMENT WINDOW:
1403- D = 5 candles (default)
1404-```
1405-
1406-**The Bearish Normal OB candle = candle[i]**
1407-
1408-#### 4.3.3 "Last Opposite Candle" Rule
1409-
1410-```
1411-If multiple consecutive bearish candles exist before a bullish expansion:
1412- The OB is the LAST bearish candle (closest to the expansion).
1413-
1414-Example:
1415- Index: 10(bear) → 11(bear) → 12(bear) → 13(BULL expansion)
1416-
1417- OB candle = index 12 (the last bearish candle)
1418- NOT index 10 or 11.
1419-
1420-Algorithm:
1421- Starting from the first expansion candle, look BACKWARDS.
1422- Find the first candle that is opposite direction.
1423- If consecutive same-direction candles exist, keep going back.
1424- The LAST one (closest to expansion) = OB candle.
1425-
1426- FORMALLY:
1427- expansion_start = i+1 (first bullish candle in the displacement)
1428- OB_index = expansion_start - 1
1429-
1430- WHILE OB_index > 0 AND Candle[OB_index] is bearish:
1431- candidate = OB_index
1432- OB_index = OB_index - 1
1433-
1434- FINAL OB = the first bearish candle found (closest to expansion)
1435- i.e., OB_index = expansion_start - 1 (simply the candle directly before expansion)
1436-```
1437-
1438-**CORRECTION — Per ICT methodology:**
1439-```
1440-The Order Block is the LAST opposite candle immediately before the impulse.
1441-So: OB = candle at index (expansion_start - 1)
1442-Do NOT look further back. It is always the single candle directly preceding the impulsive move.
1443-```

1447-### 4.4 TYPE 2: Mitigation Block – Definition
1448-
1449-#### 4.4.1 Bullish Mitigation Block
1450-
1451-**Definition:** A zone where institutions revisit a previous bullish imbalance to fill unfilled buy orders before continuing upward.
1452-
1453-```
1454-CONDITIONS for Bullish Mitigation Block:
1455-
1456-1. INITIAL BULLISH MOVE:
1457- At some index a, price makes a bullish impulse upward.
1458- This creates an imbalance/liquidity zone between index a and the high of that move.
1459-
1460-2. DEEPER RETRACEMENT:
1461- At some later index b (b > a), price retraces DEEPER than the initial pullback,
1462- going into the imbalance zone left by the move at (a).
1463-
1464-3. CONTINUATION:
1465- After reaching the mitigation zone at index b, price resumes bullish direction
1466- and creates a new higher high.
1467-
1468-DETECTION ALGORITHM:
1469- Step 1: Find a bullish impulse move (same criteria as displacement: >= 2*ATR)
1470- Step 2: Mark the BASE of that move as the imbalance zone
1471- Step 3: Wait for price to retrace INTO that zone (deeper retracement)
1472- Step 4: The candle that forms at the deepest point of retracement = Mitigation Block
1473- Step 5: Price must then continue bullish (new high within D=5 candles)
1474-
1475-MITIGATION BLOCK CANDLE:
1476- The last bearish candle at the deepest point of the retracement
1477- before the bullish continuation begins.
1478-```

1482-```

1484-
1485-1. INITIAL BEARISH MOVE: Price makes a bearish impulse downward.
1486-2. DEEPER RETRACEMENT: Price retraces upward into the imbalance zone.
1487-3. CONTINUATION: After reaching the mitigation zone, price resumes bearish.
1488-
1489-MITIGATION BLOCK CANDLE:
1490- The last bullish candle at the highest point of the retracement
1491- before the bearish continuation begins.
1492-```

1494-### 4.5 TYPE 3: Breaker Block – Definition
1495-
1496-#### 4.5.1 Bullish Breaker Block
1497-
1498-**Definition:** A previously bearish Order Block that FAILED (price broke through it), then after a market structure shift, it acts as bullish support.
1499-
1500-```
1501-CONDITIONS for Bullish Breaker Block:
1502-
1503-1. ORIGINAL BEARISH OB EXISTS:
1504- At index a, a valid Bearish Normal OB was identified.
1505- OB_High = Body_High[a] = max(Open[a], Close[a])
1506- OB_Low = Body_Low[a] = min(Open[a], Close[a])
1507-
1508-2. OB FAILURE (price breaks above):
1509- At some index b (b > a):
1510- High[b] > OB_High
1511- This means the bearish OB has FAILED to hold as resistance.
1512-
1513-3. MARKET STRUCTURE SHIFT:
1514- After the break above at index b, a new higher high is formed.
1515- A new swing high exists above OB_High.
1516-
1517- AND the structure shifts bullish:
1518- A higher low forms after the break.
1519-
1520-4. RETEST:
1521- Price retraces back DOWN to the original failed bearish OB zone.
1522- When it reaches this zone, the failed bearish OB now acts as BULLISH SUPPORT.
1523-
1524-BREAKER BLOCK ZONE:
1525- Same boundaries as the original failed bearish OB:
1526- Top = max(Open[a], Close[a]) (body high of original OB)
1527- Bottom = min(Open[a], Close[a]) (body low of original OB)
1528-```
1529-
1530-#### 4.5.2 Bearish Breaker Block
1531-
1532-```
1533-CONDITIONS for Bearish Breaker Block:
1534-
1535-1. ORIGINAL BULLISH OB EXISTS at index a.
1536-2. OB FAILURE: Price breaks BELOW OB_Low at some index b.
1537-3. MARKET STRUCTURE SHIFT: Lower low forms, structure shifts bearish.
1538-4. RETEST: Price retraces UP to the failed bullish OB zone.
1539- The failed bullish OB now acts as BEARISH RESISTANCE.
1540-
1541-BREAKER BLOCK ZONE:
1542- Top = max(Open[a], Close[a])
1543- Bottom = min(Open[a], Close[a])
1544-```

1548-### 4.6 Order Block Boundaries – CRITICAL SPECIFICATION
1549-
1550-**PER STRATEGY DOCUMENT: Order Block range is defined using CANDLE BODY ONLY. Wicks are EXCLUDED.**
1551-
1552-```
1553-For ANY Order Block candle at index i:
1554-
1555- OB_TOP = max(Open[i], Close[i]) ← Body High
1556- OB_BOTTOM = min(Open[i], Close[i]) ← Body Low
1557- OB_RANGE = OB_TOP - OB_BOTTOM
1558- OB_50% = OB_BOTTOM + 0.50 * OB_RANGE = (OB_TOP + OB_BOTTOM) / 2
1559-
1560-EXCLUDED:
1561- High[i] → NOT used for OB boundary (this is wick)

1570- │
1571- │ BODY
1572- │
1573- OB_50% ──┤─────── midpoint ──────────── ENTRY LEVEL
1574- │
1575- │ BODY
1576- │
1577- OB_BOT ──┤─────── min(Open, Close) ──── BOTTOM of Order Block

1582-### 4.7 Mitigation – Complete Definition
1583-
1584-**"Mitigation" means: price has REVISITED the Order Block zone after its formation.**
1585-
1586-An Order Block transitions from UNMITIGATED to MITIGATED when price returns to its zone.
1587-
1588-#### 4.7.1 Mitigation Condition – Formal Definition
1589-
1590-```
1591-Given Order Block formed at index i:
1592- OB_TOP = max(Open[i], Close[i])
1593- OB_BOTTOM = min(Open[i], Close[i])
1594-
1595-The OB is MITIGATED if ANY candle at index k (where k > i) satisfies:
1596-
1597- FOR BULLISH OB (price must come DOWN to touch it):
1598- Candle[k].Low <= OB_TOP
1599-
1600- Meaning: The candle's wick low reaches INTO or BELOW the top of the OB zone.
1601-
1602- FOR BEARISH OB (price must come UP to touch it):
1603- Candle[k].High >= OB_BOTTOM
1604-
1605- Meaning: The candle's wick high reaches INTO or ABOVE the bottom of the OB zone.
1606-```
1607-
1608-**IMPORTANT: WICK COUNTS for mitigation checking (even though OB boundaries use body only).**
1609-
1610-```
1611-MITIGATION CHECK USES:
1612- - OB boundaries: BODY (Open/Close)
1613- - Price reaching OB: WICK (High/Low of subsequent candles)
1614-
1615-This is intentional:
1616- - The ORDER BLOCK zone is defined by institutional candle body
1617- - Whether price TOUCHED it is measured by actual price movement (wicks)
1618-```
1619-
1620-
1621-
1622-#### 4.7.2 Mitigation Types
1623-
1624-```
1625-FULL MITIGATION (Order Block completely consumed):
1626-
1627- For Bullish OB:
1628- A candle k exists where: Low[k] <= OB_BOTTOM
1629- Price has penetrated the ENTIRE OB zone (passed through bottom).
1630-
1631- For Bearish OB:
1632- A candle k exists where: High[k] >= OB_TOP
1633- Price has penetrated the ENTIRE OB zone (passed through top).
1634-
1635-PARTIAL MITIGATION (Only touched, not fully consumed):
1636-
1637- For Bullish OB:
1638- A candle k exists where: Low[k] <= OB_TOP AND Low[k] > OB_BOTTOM
1639- Price entered the OB zone but did not pass through it completely.
1640-
1641- For Bearish OB:
1642- A candle k exists where: High[k] >= OB_BOTTOM AND High[k] < OB_TOP
1643- Price entered the OB zone but did not pass through it completely.
1644-```
1645-
1646-**RULE FOR THIS STRATEGY:**
1647-```
1648-BOTH partial and full mitigation count as MITIGATED.
1649-Once price enters the OB zone at ALL (even by a single pip), the OB is mitigated.
1650-
1651-MITIGATED (Bullish OB) = TRUE if ∃ k > i : Low[k] <= OB_TOP
1652-MITIGATED (Bearish OB) = TRUE if ∃ k > i : High[k] >= OB_BOTTOM
1653-
1654-UNMITIGATED means: NO candle after formation has entered the OB zone.
1655-```
1656-
1657-#### 4.7.3 Does Wick Count for Mitigation?
1658-
1659-```
1660-YES. WICK COUNTS.
1661-
1662-If a candle's wick (Low or High) touches the OB boundary → MITIGATED.
1663-If only the body touches but wick doesn't extend → MITIGATED (body is within wick range).
1664-
1665-The check is on the wick extremes:
1666- Low[k] for bullish OB (checking if price came down)
1667- High[k] for bearish OB (checking if price came up)
1668-```
1669-
1670-#### 4.7.4 Does Close Count?
1671-
1672-```
1673-Close is IRRELEVANT for mitigation checking.
1674-Mitigation is determined by whether price REACHED the zone, not where it closed.
1675-
1676-A candle that wicks into the OB zone but closes outside it → STILL MITIGATED.
1677-```
1678-
1679-#### 4.7.5 Tolerance for Mitigation
1680-
1681-```
1682-MITIGATION_TOLERANCE = 0.0001 (1 pip for forex)
1683- = 1.0 (1 point for indices)
1684-
1685-Bullish OB is MITIGATED if:
1686- Low[k] <= OB_TOP + MITIGATION_TOLERANCE
1687-
1688-Bearish OB is MITIGATED if:
1689- High[k] >= OB_BOTTOM - MITIGATION_TOLERANCE
1690-
1691-This tolerance means: if price gets within 1 pip of the OB zone,
1692-it counts as mitigated (price effectively "tested" the zone).
1693-```

1696-
1697-```

29+### 1.1 Overview
30+
31+A "swing" is a local extremum (peak or trough) in price data. The bot must identify these points on 1H and 4H candle data to establish the "dealing range" for Fibonacci calculations.
32+
33+### 1.2 Candle Data Structure
34+
35+Every candle at index `i` has the following properties:
36+
37+```
38+Candle[i] = {
39+ Open: O[i], // Opening price (body boundary)
40+ High: H[i], // Highest price reached (wick tip)
41+ Low: L[i], // Lowest price reached (wick tip)
42+ Close: C[i], // Closing price (body boundary)
43+ Time: T[i] // Candle open timestamp
44+}
45+```
46+
47+**Body boundaries:**
48+```
49+Body_High[i] = max(O[i], C[i])
50+Body_Low[i] = min(O[i], C[i])
51+```
52+
53+### 1.3 Candle Indexing Convention
54+
55+```
56+Index 0 = OLDEST candle in dataset (leftmost)
57+Index N = NEWEST candle (rightmost, most recent)
58+
59+For a candle at index i:
60+ Left candles: i-1, i-2, i-3, ... (older)
61+ Right candles: i+1, i+2, i+3, ... (newer)
62+```
63+
64+### 1.4 Configuration Parameter: Lookback (L)
65+
66+```
67+L = number of candles to compare on EACH side
68+DEFAULT: L = 3
69+
70+This means:
71+- Compare 3 candles to the LEFT
72+- Compare 3 candles to the RIGHT
73+- Total window = 2L + 1 = 7 candles
74+```
75+
76+**Rationale:** L=3 provides a balance between noise filtering and responsiveness on 1H/4H charts. L=1 would produce too many false swings; L=5 would miss relevant shorter-term structures.
77+
78+
79+
80+### 1.5 Swing High – Mathematical Definition
81+
82+A candle at index `i` is a **Swing High** if and only if ALL of the following conditions are TRUE:
83+
84+```
85+CONDITION SET (Swing High at index i):
86+
87+ FOR ALL j WHERE j ∈ {1, 2, 3, ..., L}:
88+ H[i] > H[i - j] // Higher than ALL L candles to the left
89+ H[i] > H[i + j] // Higher than ALL L candles to the right
90+
91+ ADDITIONALLY:
92+ i >= L // Enough candles exist on the left
93+ i <= N - L // Enough candles exist on the right (confirmation)
94+```
95+
96+**Formal notation:**
97+```
98+SwingHigh(i) = TRUE iff ∀ j ∈ [1, L]: H[i] > H[i-j] AND H[i] > H[i+j]
99+```
100+
101+**The swing high VALUE is:** `H[i]` (the wick high, NOT the body high)
102+
103+### 1.6 Swing Low – Mathematical Definition
104+
105+A candle at index `i` is a **Swing Low** if and only if ALL of the following conditions are TRUE:
106+
107+```
108+CONDITION SET (Swing Low at index i):
109+
110+ FOR ALL j WHERE j ∈ {1, 2, 3, ..., L}:
111+ L[i] < L[i - j] // Lower than ALL L candles to the left
112+ L[i] < L[i + j] // Lower than ALL L candles to the right
113+
114+ ADDITIONALLY:
115+ i >= L // Enough candles exist on the left
116+ i <= N - L // Enough candles exist on the right (confirmation)
117+```
118+
119+**Formal notation:**
120+```
121+SwingLow(i) = TRUE iff ∀ j ∈ [1, L]: L[i] < L[i-j] AND L[i] < L[i+j]
122+```
123+
124+**The swing low VALUE is:** `L[i]` (the wick low, NOT the body low)
125+
126+
127+
128+### 1.7 Measurement Basis: WICK ONLY
129+
130+**CRITICAL RULE:** Swing detection uses ONLY wick extremes (H[i] and L[i]), NEVER candle body.
131+
132+```
133+Swing High price = H[i] (NOT max(O[i], C[i]))
134+Swing Low price = L[i] (NOT min(O[i], C[i]))
135+```
136+
137+**Reason:** Wicks represent the true extreme of institutional activity at that moment.
138+
139+### 1.8 Confirmation Requirement
140+
141+A swing is ONLY confirmed after `L` candles have formed to its right.
142+
143+```
144+Swing High at index i is CONFIRMED when candle at index (i + L) has CLOSED.
145+Swing Low at index i is CONFIRMED when candle at index (i + L) has CLOSED.
146+```
147+
148+**Implication:** The bot cannot identify a swing in real-time on the current forming candle. It must wait for L candles to close after the suspected swing candle.
149+
150+**Example (L=3):**
151+```
152+Candle index: ... 10, 11, 12, 13, 14, 15 ...
153+ ^
154+ Suspected swing at i=12
155+
156+Confirmation: Candle 15 must CLOSE before swing at i=12 is confirmed.
157+The bot can only use this swing after T[15] + candle_duration.
158+```
159+
160+### 1.9 Equal Highs / Equal Lows Handling
161+
162+**Problem:** What if `H[i] == H[i-1]` or `H[i] == H[i+1]`?
163+
164+**Rule: STRICT INEQUALITY is required.**
165+
166+```
167+If H[i] == H[i-j] for ANY j ∈ [1, L]: SwingHigh(i) = FALSE
168+If H[i] == H[i+j] for ANY j ∈ [1, L]: SwingHigh(i) = FALSE
169+
170+If L[i] == L[i-j] for ANY j ∈ [1, L]: SwingLow(i) = FALSE
171+If L[i] == L[i+j] for ANY j ∈ [1, L]: SwingLow(i) = FALSE
172+```
173+
174+**Tolerance Exception:**
175+```
176+EQUAL_TOLERANCE = 0.00001 (for forex pairs with 5 decimal places)
177+ = 0.1 (for indices/metals with 1 decimal place)
178+
179+"Equal" means: |H[i] - H[j]| <= EQUAL_TOLERANCE
180+
181+If prices are "equal" within tolerance → swing is INVALID at that index.
182+```
183+
184+**Rationale:** Equal highs/lows represent liquidity pools (stop hunts), not true swing extremes. The bot should NOT use them as swing anchors for Fibonacci.
185+
186+
187+
188+### 1.10 Minimum Spacing Between Swings
189+
190+**Problem:** Two swing highs forming on adjacent candles would produce an unreliable dealing range.
191+
192+**Rule:**
193+```
194+MIN_SWING_DISTANCE = 2 * L + 1 = 7 candles (when L=3)
195+
196+If SwingHigh(i) = TRUE and SwingHigh(j) = TRUE:
197+ If |i - j| < MIN_SWING_DISTANCE:
198+ KEEP the swing with the HIGHER H[] value
199+ DISCARD the other
200+
201+If SwingLow(i) = TRUE and SwingLow(j) = TRUE:
202+ If |i - j| < MIN_SWING_DISTANCE:
203+ KEEP the swing with the LOWER L[] value
204+ DISCARD the other
205+```
206+
207+**Example:**
208+```
209+SwingHigh at i=10: H[10] = 1.2500
210+SwingHigh at i=13: H[13] = 1.2520
211+
212+Distance = |13-10| = 3 < 7 (MIN_SWING_DISTANCE)
213+
214+KEEP i=13 (H=1.2520 is higher)
215+DISCARD i=10
216+```
217+
218+### 1.11 Nested Swings
219+
220+**Definition:** A nested swing is a minor swing that forms INSIDE the range of a larger swing structure.
221+
222+```
223+Given SwingHigh(a) and SwingLow(b) form a dealing range:
224+ Range_High = H[a]
225+ Range_Low = L[b]
226+
227+A nested swing at index c is one where:
228+ L[b] < H[c] < H[a] (for nested swing high)
229+ L[b] < L[c] < H[a] (for nested swing low)
230+```
231+
232+**Rule:** The bot should use the MOST RECENT valid swing pair (high + low) that satisfies all validation criteria. Nested swings within a larger range are IGNORED unless they form a new validated pair themselves.
233+
234+### 1.12 Multiple Swing Highs / Overlapping Swings
235+
236+**Scenario:** Multiple valid swing highs exist in the lookback window.
237+
238+**Selection Rule:**
239+```
240+LOOKBACK_WINDOW = 100 candles (configurable)
241+
242+1. Scan from index (N - LOOKBACK_WINDOW) to index (N - L)
243+2. Collect ALL valid swing highs into list: SH_list[]
244+3. Collect ALL valid swing lows into list: SL_list[]
245+4. Apply minimum spacing filter (Section 1.10)
246+5. Select the MOST RECENT swing high from filtered SH_list
247+6. Select the MOST RECENT swing low from filtered SL_list
248+7. The pair (most_recent_SH, most_recent_SL) defines the dealing range
249+
250+CONSTRAINT: The selected swing high and swing low must form a LOGICAL pair:
251+ - Swing High index ≠ Swing Low index
252+ - There must be at least 5 candles between them: |SH_index - SL_index| >= 5
253+```
254+
255+

257+### 1.13 Scanning Algorithm – Pseudo Code
258+
259+```python
260+def detect_swings(candles, L=3, lookback_window=100):
261+ """
262+ Scans candle array and returns validated swing highs and swing lows.
263+
264+ Parameters:
265+ candles: array of Candle objects with .High, .Low, .Open, .Close, .Time
266+ L: number of candles to compare on each side (default=3)
267+ lookback_window: how many candles back to scan (default=100)
268+
269+ Returns:
270+ swing_highs: list of {index, price, time}
271+ swing_lows: list of {index, price, time}
272+ """
273+
274+ N = len(candles) - 1 # Last candle index
275+ start = max(L, N - lookback_window)
276+ end = N - L # Cannot confirm swings in last L candles
277+
278+ raw_swing_highs = []
279+ raw_swing_lows = []
280+
281+ # STEP 1: Identify all raw swing points
282+ for i in range(start, end + 1):
283+
284+ # --- Check Swing High ---
285+ is_swing_high = True
286+ for j in range(1, L + 1):
287+ if candles[i].High <= candles[i - j].High:
288+ is_swing_high = False
289+ break
290+ if candles[i].High <= candles[i + j].High:
291+ is_swing_high = False
292+ break
293+
294+ if is_swing_high:
295+ raw_swing_highs.append({
296+ 'index': i,
297+ 'price': candles[i].High,
298+ 'time': candles[i].Time
299+ })
300+
301+ # --- Check Swing Low ---
302+ is_swing_low = True
303+ for j in range(1, L + 1):
304+ if candles[i].Low >= candles[i - j].Low:
305+ is_swing_low = False
306+ break
307+ if candles[i].Low >= candles[i + j].Low:
308+ is_swing_low = False
309+ break
310+
311+ if is_swing_low:
312+ raw_swing_lows.append({
313+ 'index': i,
314+ 'price': candles[i].Low,
315+ 'time': candles[i].Time
316+ })
317+
318+ # STEP 2: Apply minimum spacing filter
319+ swing_highs = filter_min_spacing(raw_swing_highs, MIN_SWING_DISTANCE, 'high')
320+ swing_lows = filter_min_spacing(raw_swing_lows, MIN_SWING_DISTANCE, 'low')
321+
322+ return swing_highs, swing_lows
323+
324+
325+def filter_min_spacing(swings, min_distance, swing_type):
326+ """
327+ Remove swings that are too close together.
328+ Keep the more extreme one (higher for highs, lower for lows).
329+ """
330+ if len(swings) <= 1:
331+ return swings
332+
333+ filtered = [swings[0]]
334+
335+ for i in range(1, len(swings)):
336+ last = filtered[-1]
337+ current = swings[i]
338+ distance = abs(current['index'] - last['index'])
339+
340+ if distance < min_distance:
341+ # Too close - keep the more extreme
342+ if swing_type == 'high':
343+ if current['price'] > last['price']:
344+ filtered[-1] = current # Replace with higher
345+ else: # low
346+ if current['price'] < last['price']:
347+ filtered[-1] = current # Replace with lower
348+ else:
349+ filtered.append(current)
350+
351+ return filtered
352+```

473+## SECTION 2: FIBONACCI PREMIUM / DISCOUNT LOGIC
474+
475+### 2.1 Overview
476+
477+Fibonacci retracement is a mathematical tool used to divide a price range into proportional zones. The bot uses it to classify the dealing range (between a swing high and swing low) into **Premium Zone** (expensive / sell area) and **Discount Zone** (cheap / buy area).
478+
479+**Key Concept:** Institutions accumulate positions in discount zones (cheap) and distribute in premium zones (expensive). The bot identifies which zone an order block sits in to determine trade direction.
480+
481+### 2.2 Core Definitions
482+
483+```
484+Dealing Range = The price distance between a validated Swing High and Swing Low
485+
486+Anchor A = Starting point of Fibonacci measurement
487+Anchor B = Ending point of Fibonacci measurement
488+
489+Equilibrium = The exact 50% midpoint of the dealing range
490+Premium Zone = Price area ABOVE equilibrium (expensive)
491+Discount Zone = Price area BELOW equilibrium (cheap)
492+```
493+
494+### 2.3 Fibonacci Anchor Points
495+
496+**CRITICAL: Fibonacci is ALWAYS drawn from wick-to-wick (not body-to-body).**
497+
498+#### For BEARISH setups (looking for sells):
499+```
500+Anchor A = Swing High = H[swing_high_index] (the wick high)
501+Anchor B = Swing Low = L[swing_low_index] (the wick low)
502+
503+Direction: TOP → BOTTOM
504+Fibonacci 0% = Swing High (Anchor A)
505+Fibonacci 100% = Swing Low (Anchor B)
506+```
507+
508+#### For BULLISH setups (looking for buys):
509+```
510+Anchor A = Swing Low = L[swing_low_index] (the wick low)
511+Anchor B = Swing High = H[swing_high_index] (the wick high)
512+
513+Direction: BOTTOM → TOP
514+Fibonacci 0% = Swing Low (Anchor A)
515+Fibonacci 100% = Swing High (Anchor B)
516+```
517+
518+### 2.4 Fibonacci Level Calculation Formula
519+
520+**Universal Formula:**
521+```
522+Fib_Level(percentage) = Anchor_A + (Anchor_B - Anchor_A) × percentage
523+```
524+
525+**For BEARISH (Anchor A = High, Anchor B = Low):**
526+```
527+Fib_Level(p) = Swing_High + (Swing_Low - Swing_High) × p
528+Fib_Level(p) = Swing_High - (Swing_High - Swing_Low) × p
529+```
530+
531+**For BULLISH (Anchor A = Low, Anchor B = High):**
532+```
533+Fib_Level(p) = Swing_Low + (Swing_High - Swing_Low) × p
534+```
535+
536+
537+
538+### 2.5 Complete Fibonacci Level Table
539+
540+The bot must calculate and store these levels:
541+
542+| Level | Percentage | Zone Classification |
543+|-------|-----------|-------------------|
544+| 0% | 0.000 | Range boundary (start) |
545+| 23.6% | 0.236 | Shallow (not used for entries) |
546+| 38.2% | 0.382 | Shallow (not used for entries) |
547+| **50%** | **0.500** | **EQUILIBRIUM (boundary line)** |
548+| **61.8%** | **0.618** | **PRIMARY institutional zone** |
549+| 70.5% | 0.705 | Deep institutional zone |
550+| 78.6% | 0.786 | Deep institutional zone |
551+| 100% | 1.000 | Range boundary (end) |
552+
553+### 2.6 Zone Classification Rules
554+
555+#### BEARISH Context (Fibonacci drawn High → Low):
556+
557+```
558+Premium Zone: All prices ABOVE the 50% level
559+ Specifically: Prices between Fib_50% and Fib_0% (Swing High)
560+
561+ Sub-zones:
562+ Shallow Premium: Fib_0% to Fib_38.2% → NOT used for entries
563+ KEY Premium: Fib_38.2% to Fib_50% → Primary sell zone
564+
565+Discount Zone: All prices BELOW the 50% level
566+ Specifically: Prices between Fib_50% and Fib_100% (Swing Low)
567+ → NOT used for bearish entries
568+
569+Equilibrium: Exactly at Fib_50%
570+ → Boundary between premium and discount
571+
572+INSTITUTIONAL INTEREST AREAS (for BEARISH sells):
573+ Priority 1: 50.0% level (equilibrium)
574+ Priority 2: 61.8% level → This means price at: High - 0.618*(High-Low)
575+ Priority 3: 78.6% level → This means price at: High - 0.786*(High-Low)
576+
577+ WAIT: In bearish context, the "premium" is where price is expensive.
578+ Since Fib is drawn from High to Low:
579+ Fib 0% = High
580+ Fib 50% = Midpoint
581+ Fib 100% = Low
582+
583+ Premium = prices from Fib_0% to Fib_50% (top half)
584+ The 50%-61.8% area RELATIVE TO THE RANGE means:
585+ Price between: High - 0.50*(High-Low) and High - 0.618*(High-Low)
586+
587+ BUT PER THE STRATEGY DOCUMENT:
588+ "Premium zone is above the 50% level, mainly the 50%–61.8% area"
589+ This means the PREMIUM is between Fib_50% and Fib_0%
590+ The KEY area is the 50% to 61.8% slice (measured from the TOP):
591+ Upper boundary: Swing_High × (1 - 0.50*range_ratio) → i.e., the 50% fib
592+ Lower boundary: Swing_High × (1 - 0.618*range_ratio) → NO
593+
594+ CORRECT INTERPRETATION:
595+ The Fibonacci levels 50%, 61.8%, 78.6% are measured FROM Anchor A.
596+ In bearish: Anchor A = High.
597+ So Fib_50% is HALFWAY DOWN from the high.
598+ "Above 50%" means: price is between Swing_High and Fib_50%
599+
600+ Premium Zone (BEARISH sell area):
601+ UPPER_BOUND = Swing_High (Fib 0%)
602+ LOWER_BOUND = Fib_50% = Swing_High - 0.50 * (Swing_High - Swing_Low)
603+
604+ KEY institutional levels within premium:
605+ 50% mark: Swing_High - 0.50 * Range
606+ 38.2% mark: Swing_High - 0.382 * Range
607+ 23.6% mark: Swing_High - 0.236 * Range
608+```
609+
610+#### BULLISH Context (Fibonacci drawn Low → High):
611+
612+```
613+Discount Zone: All prices BELOW the 50% level
614+ Specifically: Prices between Fib_0% (Swing Low) and Fib_50%
615+
616+Equilibrium: Exactly at Fib_50%
617+ → Boundary between discount and premium
618+
619+INSTITUTIONAL INTEREST AREAS (for BULLISH buys):
620+ The discount zone is BELOW 50%, mainly 50%-61.8% area.
621+
622+ Since Fib is drawn from Low to High:
623+ Fib 0% = Low
624+ Fib 50% = Midpoint
625+ Fib 100% = High
626+
627+ Discount Zone (BULLISH buy area):
628+ UPPER_BOUND = Fib_50% = Swing_Low + 0.50 * (Swing_High - Swing_Low)
629+ LOWER_BOUND = Swing_Low (Fib 0%)
630+
631+ KEY institutional levels within discount:
632+ 50% mark: Swing_Low + 0.50 * Range (top of discount)
633+ 38.2% mark: Swing_Low + 0.382 * Range
634+ 23.6% mark: Swing_Low + 0.236 * Range
635+```

639+### 2.7 CORRECTED & SIMPLIFIED Zone Model
640+
641+After careful analysis of the strategy document, here is the definitive model:
642+
643+```
644+┌─────────────────────────────────────────────────────────┐
645+│ DEALING RANGE │
646+│ │
647+│ Swing High ─────────────────────── (Fib 0% bearish) │
648+│ │ │
649+│ │ ┌─── PREMIUM ZONE (Sell Area) ───┐ │
650+│ │ │ Institutional levels: │ │
651+│ │ │ OTE: 62%-79% from top │ │
652+│ │ │ (= Fib 0.382 to 0.214) │ │
653+│ │ └─────────────────────────────────┘ │
654+│ │ │
655+│ Equilibrium (50%) ──────────────── MIDPOINT │
656+│ │ │
657+│ │ ┌─── DISCOUNT ZONE (Buy Area) ───┐ │
658+│ │ │ Institutional levels: │ │
659+│ │ │ OTE: 62%-79% from bottom │ │
660+│ │ │ (= Fib 0.382 to 0.214) │ │
661+│ │ └─────────────────────────────────┘ │
662+│ │ │
663+│ Swing Low ──────────────────────── (Fib 0% bullish) │
664+└─────────────────────────────────────────────────────────┘
665+```

667+**FINAL SIMPLIFIED RULES:**
668+
669+```
670+Range = Swing_High - Swing_Low
671+Equilibrium = Swing_Low + 0.50 * Range = (Swing_High + Swing_Low) / 2
672+
673+PREMIUM ZONE (for bearish/sell entries):
674+ Any price P where: P > Equilibrium
675+ Specifically: Equilibrium < P <= Swing_High
676+
677+ KEY SUB-ZONE (highest probability):
678+ Lower = Equilibrium = Swing_Low + 0.50 * Range
679+ Upper = Swing_Low + 0.618 * Range (the 61.8% fib from low)
680+
681+ Translated: prices between 50% and 61.8% of the range measured from the LOW
682+ Which equals the zone between 50% and 38.2% measured from the HIGH
683+
684+DISCOUNT ZONE (for bullish/buy entries):
685+ Any price P where: P < Equilibrium
686+ Specifically: Swing_Low <= P < Equilibrium
687+
688+ KEY SUB-ZONE (highest probability):
689+ Upper = Equilibrium = Swing_Low + 0.50 * Range
690+ Lower = Swing_Low + 0.382 * Range (the 38.2% fib from low)
691+

934+## SECTION 3: SWING VALIDATION USING 50% RULE
935+
936+### 3.1 Overview
937+
938+This is a **custom invalidation rule** that prevents the bot from using stale or already-reacted-to swings. The core principle:
939+
940+> **A swing becomes INVALID if price has already touched or crossed the 50% equilibrium level AFTER the swing was confirmed.**
941+
942+**Rationale:** Once price reaches the 50% equilibrium of a dealing range, institutions have already partially filled their orders. The original swing structure has been "used up" and should not be relied upon for new entries.
943+
944+### 3.2 Core Rule – Formal Definition
945+
946+```
947+Given:
948+ - SwingHigh confirmed at index SH_idx, price = H[SH_idx]
949+ - SwingLow confirmed at index SL_idx, price = L[SL_idx]
950+ - Confirmation candle index = max(SH_idx, SL_idx) + L
951+ - Equilibrium = (H[SH_idx] + L[SL_idx]) / 2
952+
953+The swing pair is VALID if and only if:
954+ FOR ALL candles k WHERE k > Confirmation_Index AND k <= Current_Index:
955+ NO candle has "touched" the Equilibrium level.
956+
957+If ANY candle touches equilibrium after confirmation:
958+ The swing pair becomes PERMANENTLY INVALID.
959+ Bot must discard it and scan for a new swing pair.
960+```
961+
962+### 3.3 Definition of "Touching" the 50% Level
963+
964+**CRITICAL QUESTION: What constitutes a "touch"?**
965+
966+**RULE: A candle "touches" the 50% level if its WICK passes through or reaches the equilibrium price.**
967+
968+```
969+For a candle at index k:
970+
971+TOUCH OCCURS if:
972+ L[k] <= Equilibrium <= H[k]
973+
974+Meaning: The candle's full range (wick low to wick high) encompasses the equilibrium price.
975+
976+This includes:
977+ - Wick touches equilibrium (body doesn't reach it)
978+ - Body crosses equilibrium
979+ - Close is at equilibrium
980+ - Open is at equilibrium
981+ - Any part of the candle overlaps with equilibrium
982+
983+TOUCH DOES NOT OCCUR if:
984+ L[k] > Equilibrium (entire candle is above equilibrium)
985+ H[k] < Equilibrium (entire candle is below equilibrium)
986+```
987+
988+### 3.4 Tolerance for "Touching"
989+
990+```
991+TOUCH_TOLERANCE = 0.0002 (2 pips for forex 5-digit pairs)
992+ = 2.0 (2 points for indices)
993+
994+A candle "touches" equilibrium if:
995+ L[k] - TOUCH_TOLERANCE <= Equilibrium <= H[k] + TOUCH_TOLERANCE
996+
997+This accounts for:
998+ - Spread variations
999+ - Minor price noise
1000+ - Broker price differences
1001+```
1002+
1003+
1004+
1005+### 3.5 Specific Touch Scenarios – Classification Table
1006+
1007+**Given: Equilibrium = 1.0100**
1008+
1009+| Scenario | Candle Data | Touch? | Reason |
1010+|----------|-------------|--------|--------|
1011+| Wick pierces exactly | H=1.0120, L=1.0080 | **YES** | L < 1.0100 < H |
1012+| Wick touches exactly | H=1.0100, L=1.0060 | **YES** | H == Equilibrium |
1013+| Body crosses, wicks extend | O=1.0110, C=1.0090, H=1.0115, L=1.0085 | **YES** | L < 1.0100 < H |
1014+| Close AT equilibrium | O=1.0120, C=1.0100, H=1.0125, L=1.0098 | **YES** | L < 1.0100 < H |
1015+| Candle entirely above | H=1.0150, L=1.0110 | **NO** | L=1.0110 > 1.0100 |
1016+| Candle entirely below | H=1.0090, L=1.0050 | **NO** | H=1.0090 < 1.0100 |
1017+| Within tolerance (barely misses) | H=1.0099, L=1.0060 | **YES** | H + 0.0002 = 1.0101 >= 1.0100 |
1018+| Outside tolerance | H=1.0095, L=1.0060 | **NO** | H + 0.0002 = 1.0097 < 1.0100 |
1019+| Gap candle that jumps over | Previous H=1.0090, Current L=1.0110 | **YES** | Price "passed through" equilibrium via gap |
1020+
1021+### 3.6 Gap Handling
1022+
1023+**Special case: Price gaps over the equilibrium without any candle body/wick touching it.**
1024+
1025+```
1026+GAP RULE:
1027+ If candle[k-1].High < Equilibrium AND candle[k].Low > Equilibrium:
1028+ → Price GAPPED OVER equilibrium (bullish gap)
1029+ → This counts as a TOUCH (invalidates the swing)
1030+
1031+ If candle[k-1].Low > Equilibrium AND candle[k].High < Equilibrium:
1032+ → Price GAPPED OVER equilibrium (bearish gap)
1033+ → This counts as a TOUCH (invalidates the swing)
1034+
1035+FORMAL:
1036+ GAP_TOUCH(k) = TRUE if:
1037+ (H[k-1] < Equilibrium AND L[k] > Equilibrium) OR
1038+ (L[k-1] > Equilibrium AND H[k] < Equilibrium)
1039+```
1040+
1041+**Rationale:** A gap through equilibrium means price has definitively passed the midpoint. The institutional interest in the original range is exhausted.
1042+
1043+### 3.7 Multiple Taps (Repeated Touches)
1044+
1045+```
1046+RULE: The FIRST touch invalidates. Multiple taps are irrelevant.
1047+
1048+Once TOUCH = TRUE for any candle after confirmation:
1049+ swing_valid = FALSE (permanently)
1050+
1051+The bot does NOT need to count multiple touches.
1052+One touch = invalidation. Done.
1053+```

1086+
1087+```

1089+ 1. Mark the pair as INVALID in memory
1090+ 2. Do NOT use this pair for any further calculations
1091+ 3. Do NOT generate any signals from order blocks found using this pair
1092+ 4. Begin scanning for the NEXT valid swing pair immediately
1093+ 5. The new scan starts from the candle AFTER the invalidation event
1094+
1095+SCANNING FOR NEW SWING:
1096+ new_scan_start = invalidation_candle_index + 1
1097+ Apply Section 1 swing detection from new_scan_start onward
1098+ Wait for L candles of confirmation for any new swing found
1099+```

1101+### 3.10 Algorithm – Pseudo Code
1102+
1103+```python
1104+def validate_swing_pair(candles, sh_index, sl_index, L=3):
1105+ """
1106+ Validates a swing pair by checking if 50% equilibrium has been touched.
1107+
1108+ Parameters:
1109+ candles: full candle array
1110+ sh_index: index of the swing high candle
1111+ sl_index: index of the swing low candle
1112+ L: lookback parameter (for confirmation calculation)
1113+
1114+ Returns:
1115+ {
1116+ 'valid': bool,
1117+ 'invalidated_at': index or None,
1118+ 'equilibrium': float
1119+ }
1120+ """
1121+ TOUCH_TOLERANCE = 0.0002 # Configure per instrument
1122+
1123+ # Calculate equilibrium
1124+ swing_high_price = candles[sh_index].High
1125+ swing_low_price = candles[sl_index].Low
1126+ equilibrium = (swing_high_price + swing_low_price) / 2
1127+
1128+ # Determine confirmation index
1129+ confirmation_index = max(sh_index, sl_index) + L
1130+
1131+ # Current candle index
1132+ current_index = len(candles) - 1
1133+
1134+ # Check all candles AFTER confirmation
1135+ for k in range(confirmation_index + 1, current_index + 1):
1136+
1137+ # Standard touch check
1138+ candle_low = candles[k].Low
1139+ candle_high = candles[k].High
1140+
1141+ if (candle_low - TOUCH_TOLERANCE) <= equilibrium <= (candle_high + TOUCH_TOLERANCE):
1142+ return {
1143+ 'valid': False,
1144+ 'invalidated_at': k,
1145+ 'equilibrium': equilibrium
1146+ }
1147+
1148+ # Gap check (if k > confirmation_index + 1)
1149+ if k > confirmation_index + 1:
1150+ prev_high = candles[k-1].High
1151+ prev_low = candles[k-1].Low
1152+
1153+ # Bullish gap over equilibrium
1154+ if prev_high < equilibrium and candle_low > equilibrium:
1155+ return {
1156+ 'valid': False,
1157+ 'invalidated_at': k,
1158+ 'equilibrium': equilibrium
1159+ }
1160+
1161+ # Bearish gap over equilibrium
1162+ if prev_low > equilibrium and candle_high < equilibrium:
1163+ return {
1164+ 'valid': False,
1165+ 'invalidated_at': k,
1166+ 'equilibrium': equilibrium
1167+ }
1168+
1169+ # No touch found - swing is still valid
1170+ return {
1171+ 'valid': True,
1172+ 'invalidated_at': None,
1173+ 'equilibrium': equilibrium
1174+ }
1175+```

1262+def monitor_swing_validity(candles, active_swing_pair):

1297+| Edge Case | Rule |
1298+|-----------|------|
1299+| Equilibrium is between two candles' ranges but no candle touches it | VALID – no touch occurred |
1300+| Candle opens exactly at equilibrium | INVALID – Open is within the candle's H/L range which includes equilibrium |
1301+| Swing High and Swing Low are on the same candle | IMPOSSIBLE – Section 1.16 prevents this |
1302+| Price touches equilibrium on the confirmation candle itself | VALID – only candles AFTER confirmation count |
1303+| New swing found but not yet confirmed | Cannot use it; wait for confirmation |
1304+| Multiple swing pairs pending | Use the MOST RECENT confirmed & valid pair |

1310+## SECTION 4: UNMITIGATED ORDER BLOCK DETECTION
1311+
1312+### 4.1 Overview
1313+
1314+An **Order Block (OB)** is a specific candle that represents institutional activity — a large order placement before a significant price move. The bot must:
1315+1. Identify Order Blocks (three types)
1316+2. Define their exact boundaries
1317+3. Track whether they have been "mitigated" (revisited) or remain "unmitigated" (untouched)
1318+
1319+Only **UNMITIGATED** Order Blocks are valid for trade entries.
1320+
1321+### 4.2 Order Block Types
1322+
1323+The strategy defines THREE types of order blocks:
1324+
1325+```
1326+1. Normal Order Block — Last opposite candle before impulsive move
1327+2. Mitigation Block — Revisited imbalance zone used before continuation
1328+3. Breaker Block — Failed order block that flips into support/resistance
1329+```
1330+
1331+---
1332+
1333+### 4.3 TYPE 1: Normal Order Block – Definition
1334+
1335+#### 4.3.1 Bullish Normal Order Block
1336+
1337+**Definition:** The last BEARISH candle before a strong bullish expansion that breaks structure upward.
1338+
1339+```
1340+CONDITIONS for Bullish Normal OB at candle index i:
1341+
1342+1. Candle[i] is BEARISH:
1343+ Close[i] < Open[i]
1344+
1345+2. Candle[i+1] (or subsequent candles) create BULLISH DISPLACEMENT:
1346+ The move from candle[i] to the next swing creates a strong upward move.
1347+
1348+ DISPLACEMENT CONDITION:
1349+ Let displacement_candles = candles from index (i+1) to (i+D) where D = displacement window
1350+
1351+ Total_Bullish_Move = max(High[i+1..i+D]) - Low[i]
1352+
1353+ Displacement is VALID if:
1354+ Total_Bullish_Move >= 2 × ATR(14)
1355+
1356+ WHERE ATR(14) = Average True Range of the last 14 candles before index i
1357+
1358+ ATR(14) calculation:
1359+ TR[k] = max(H[k] - L[k], |H[k] - C[k-1]|, |L[k] - C[k-1]|)
1360+ ATR(14) = (1/14) × Σ TR[k] for k = (i-14) to (i-1)
1361+
1362+3. STRUCTURE BREAK:
1363+ After the bullish displacement, price must break above the most recent swing high
1364+ that existed BEFORE candle[i].
1365+
1366+ Let previous_swing_high = most recent SwingHigh price before index i
1367+
1368+ Structure_Break = TRUE if:
1369+ max(High[i+1..i+D]) > previous_swing_high
1370+
1371+4. DISPLACEMENT WINDOW:
1372+ D = 5 candles (default)
1373+ The bullish move must occur within 5 candles after the OB candle.
1374+```
1375+
1376+**The Bullish Normal OB candle = candle[i]**
1377+
1378+
1379+
1380+#### 4.3.2 Bearish Normal Order Block
1381+
1382+**Definition:** The last BULLISH candle before a strong bearish expansion that breaks structure downward.
1383+
1384+```
1385+CONDITIONS for Bearish Normal OB at candle index i:
1386+
1387+1. Candle[i] is BULLISH:
1388+ Close[i] > Open[i]
1389+
1390+2. BEARISH DISPLACEMENT:
1391+ Total_Bearish_Move = High[i] - min(Low[i+1..i+D])
1392+
1393+ Displacement is VALID if:
1394+ Total_Bearish_Move >= 2 × ATR(14)
1395+
1396+3. STRUCTURE BREAK:
1397+ Let previous_swing_low = most recent SwingLow price before index i
1398+
1399+ Structure_Break = TRUE if:
1400+ min(Low[i+1..i+D]) < previous_swing_low
1401+
1402+4. DISPLACEMENT WINDOW:
1403+ D = 5 candles (default)
1404+```
1405+
1406+**The Bearish Normal OB candle = candle[i]**
1407+
1408+#### 4.3.3 "Last Opposite Candle" Rule
1409+
1410+```
1411+If multiple consecutive bearish candles exist before a bullish expansion:
1412+ The OB is the LAST bearish candle (closest to the expansion).
1413+
1414+Example:
1415+ Index: 10(bear) → 11(bear) → 12(bear) → 13(BULL expansion)
1416+
1417+ OB candle = index 12 (the last bearish candle)
1418+ NOT index 10 or 11.
1419+
1420+Algorithm:
1421+ Starting from the first expansion candle, look BACKWARDS.
1422+ Find the first candle that is opposite direction.
1423+ If consecutive same-direction candles exist, keep going back.
1424+ The LAST one (closest to expansion) = OB candle.
1425+
1426+ FORMALLY:
1427+ expansion_start = i+1 (first bullish candle in the displacement)
1428+ OB_index = expansion_start - 1
1429+
1430+ WHILE OB_index > 0 AND Candle[OB_index] is bearish:
1431+ candidate = OB_index
1432+ OB_index = OB_index - 1
1433+
1434+ FINAL OB = the first bearish candle found (closest to expansion)
1435+ i.e., OB_index = expansion_start - 1 (simply the candle directly before expansion)
1436+```
1437+
1438+**CORRECTION — Per ICT methodology:**
1439+```
1440+The Order Block is the LAST opposite candle immediately before the impulse.
1441+So: OB = candle at index (expansion_start - 1)
1442+Do NOT look further back. It is always the single candle directly preceding the impulsive move.
1443+```
1444+
1445+
1446+
1447+### 4.4 TYPE 2: Mitigation Block – Definition
1448+
1449+#### 4.4.1 Bullish Mitigation Block
1450+
1451+**Definition:** A zone where institutions revisit a previous bullish imbalance to fill unfilled buy orders before continuing upward.
1452+
1453+```
1454+CONDITIONS for Bullish Mitigation Block:
1455+
1456+1. INITIAL BULLISH MOVE:
1457+ At some index a, price makes a bullish impulse upward.
1458+ This creates an imbalance/liquidity zone between index a and the high of that move.
1459+
1460+2. DEEPER RETRACEMENT:
1461+ At some later index b (b > a), price retraces DEEPER than the initial pullback,
1462+ going into the imbalance zone left by the move at (a).
1463+
1464+3. CONTINUATION:
1465+ After reaching the mitigation zone at index b, price resumes bullish direction
1466+ and creates a new higher high.
1467+
1468+DETECTION ALGORITHM:
1469+ Step 1: Find a bullish impulse move (same criteria as displacement: >= 2*ATR)
1470+ Step 2: Mark the BASE of that move as the imbalance zone
1471+ Step 3: Wait for price to retrace INTO that zone (deeper retracement)
1472+ Step 4: The candle that forms at the deepest point of retracement = Mitigation Block
1473+ Step 5: Price must then continue bullish (new high within D=5 candles)
1474+
1475+MITIGATION BLOCK CANDLE:
1476+ The last bearish candle at the deepest point of the retracement
1477+ before the bullish continuation begins.
1478+```
1479+
1480+#### 4.4.2 Bearish Mitigation Block
1481+
1482+```
1483+CONDITIONS for Bearish Mitigation Block:
1484+
1485+1. INITIAL BEARISH MOVE: Price makes a bearish impulse downward.
1486+2. DEEPER RETRACEMENT: Price retraces upward into the imbalance zone.
1487+3. CONTINUATION: After reaching the mitigation zone, price resumes bearish.
1488+
1489+MITIGATION BLOCK CANDLE:
1490+ The last bullish candle at the highest point of the retracement
1491+ before the bearish continuation begins.
1492+```
1493+
1494+### 4.5 TYPE 3: Breaker Block – Definition
1495+
1496+#### 4.5.1 Bullish Breaker Block
1497+
1498+**Definition:** A previously bearish Order Block that FAILED (price broke through it), then after a market structure shift, it acts as bullish support.
1499+
1500+```
1501+CONDITIONS for Bullish Breaker Block:
1502+
1503+1. ORIGINAL BEARISH OB EXISTS:
1504+ At index a, a valid Bearish Normal OB was identified.
1505+ OB_High = Body_High[a] = max(Open[a], Close[a])
1506+ OB_Low = Body_Low[a] = min(Open[a], Close[a])
1507+
1508+2. OB FAILURE (price breaks above):
1509+ At some index b (b > a):
1510+ High[b] > OB_High
1511+ This means the bearish OB has FAILED to hold as resistance.
1512+
1513+3. MARKET STRUCTURE SHIFT:
1514+ After the break above at index b, a new higher high is formed.
1515+ A new swing high exists above OB_High.
1516+
1517+ AND the structure shifts bullish:
1518+ A higher low forms after the break.
1519+
1520+4. RETEST:
1521+ Price retraces back DOWN to the original failed bearish OB zone.
1522+ When it reaches this zone, the failed bearish OB now acts as BULLISH SUPPORT.
1523+
1524+BREAKER BLOCK ZONE:
1525+ Same boundaries as the original failed bearish OB:
1526+ Top = max(Open[a], Close[a]) (body high of original OB)
1527+ Bottom = min(Open[a], Close[a]) (body low of original OB)
1528+```
1529+
1530+#### 4.5.2 Bearish Breaker Block
1531+
1532+```
1533+CONDITIONS for Bearish Breaker Block:
1534+
1535+1. ORIGINAL BULLISH OB EXISTS at index a.
1536+2. OB FAILURE: Price breaks BELOW OB_Low at some index b.
1537+3. MARKET STRUCTURE SHIFT: Lower low forms, structure shifts bearish.
1538+4. RETEST: Price retraces UP to the failed bullish OB zone.
1539+ The failed bullish OB now acts as BEARISH RESISTANCE.
1540+
1541+BREAKER BLOCK ZONE:
1542+ Top = max(Open[a], Close[a])
1543+ Bottom = min(Open[a], Close[a])
1544+```
1545+
1546+

1548+### 4.6 Order Block Boundaries – CRITICAL SPECIFICATION
1549+
1550+**PER STRATEGY DOCUMENT: Order Block range is defined using CANDLE BODY ONLY. Wicks are EXCLUDED.**
1551+
1552+```
1553+For ANY Order Block candle at index i:
1554+
1555+ OB_TOP = max(Open[i], Close[i]) ← Body High
1556+ OB_BOTTOM = min(Open[i], Close[i]) ← Body Low
1557+ OB_RANGE = OB_TOP - OB_BOTTOM
1558+ OB_50% = OB_BOTTOM + 0.50 * OB_RANGE = (OB_TOP + OB_BOTTOM) / 2
1559+
1560+EXCLUDED:
1561+ High[i] → NOT used for OB boundary (this is wick)
1562+ Low[i] → NOT used for OB boundary (this is wick)
1563+```
1564+
1565+**Visual:**
1566+```
1567+ High[i] ─────── wick (EXCLUDED from OB range)
1568+ │
1569+ OB_TOP ──┤─────── max(Open, Close) ──── TOP of Order Block
1570+ │
1571+ │ BODY
1572+ │
1573+ OB_50% ──┤─────── midpoint ──────────── ENTRY LEVEL
1574+ │
1575+ │ BODY
1576+ │
1577+ OB_BOT ──┤─────── min(Open, Close) ──── BOTTOM of Order Block
1578+ │
1579+ Low[i] ──────── wick (EXCLUDED from OB range)
1580+```
1581+
1582+### 4.7 Mitigation – Complete Definition
1583+
1584+**"Mitigation" means: price has REVISITED the Order Block zone after its formation.**
1585+
1586+An Order Block transitions from UNMITIGATED to MITIGATED when price returns to its zone.
1587+
1588+#### 4.7.1 Mitigation Condition – Formal Definition
1589+
1590+```
1591+Given Order Block formed at index i:
1592+ OB_TOP = max(Open[i], Close[i])
1593+ OB_BOTTOM = min(Open[i], Close[i])
1594+
1595+The OB is MITIGATED if ANY candle at index k (where k > i) satisfies:
1596+
1597+ FOR BULLISH OB (price must come DOWN to touch it):
1598+ Candle[k].Low <= OB_TOP
1599+
1600+ Meaning: The candle's wick low reaches INTO or BELOW the top of the OB zone.
1601+
1602+ FOR BEARISH OB (price must come UP to touch it):
1603+ Candle[k].High >= OB_BOTTOM
1604+
1605+ Meaning: The candle's wick high reaches INTO or ABOVE the bottom of the OB zone.
1606+```
1607+
1608+**IMPORTANT: WICK COUNTS for mitigation checking (even though OB boundaries use body only).**
1609+
1610+```
1611+MITIGATION CHECK USES:
1612+ - OB boundaries: BODY (Open/Close)
1613+ - Price reaching OB: WICK (High/Low of subsequent candles)
1614+
1615+This is intentional:
1616+ - The ORDER BLOCK zone is defined by institutional candle body
1617+ - Whether price TOUCHED it is measured by actual price movement (wicks)
1618+```
1619+
1620+
1621+
1622+#### 4.7.2 Mitigation Types
1623+
1624+```
1625+FULL MITIGATION (Order Block completely consumed):
1626+
1627+ For Bullish OB:
1628+ A candle k exists where: Low[k] <= OB_BOTTOM
1629+ Price has penetrated the ENTIRE OB zone (passed through bottom).
1630+
1631+ For Bearish OB:
1632+ A candle k exists where: High[k] >= OB_TOP
1633+ Price has penetrated the ENTIRE OB zone (passed through top).
1634+
1635+PARTIAL MITIGATION (Only touched, not fully consumed):
1636+
1637+ For Bullish OB:
1638+ A candle k exists where: Low[k] <= OB_TOP AND Low[k] > OB_BOTTOM
1639+ Price entered the OB zone but did not pass through it completely.
1640+
1641+ For Bearish OB:
1642+ A candle k exists where: High[k] >= OB_BOTTOM AND High[k] < OB_TOP
1643+ Price entered the OB zone but did not pass through it completely.
1644+```
1645+
1646+**RULE FOR THIS STRATEGY:**
1647+```
1648+BOTH partial and full mitigation count as MITIGATED.
1649+Once price enters the OB zone at ALL (even by a single pip), the OB is mitigated.
1650+
1651+MITIGATED (Bullish OB) = TRUE if ∃ k > i : Low[k] <= OB_TOP
1652+MITIGATED (Bearish OB) = TRUE if ∃ k > i : High[k] >= OB_BOTTOM
1653+
1654+UNMITIGATED means: NO candle after formation has entered the OB zone.
1655+```
1656+
1657+#### 4.7.3 Does Wick Count for Mitigation?
1658+
1659+```
1660+YES. WICK COUNTS.
1661+
1662+If a candle's wick (Low or High) touches the OB boundary → MITIGATED.
1663+If only the body touches but wick doesn't extend → MITIGATED (body is within wick range).
1664+
1665+The check is on the wick extremes:
1666+ Low[k] for bullish OB (checking if price came down)
1667+ High[k] for bearish OB (checking if price came up)
1668+```
1669+
1670+#### 4.7.4 Does Close Count?
1671+
1672+```
1673+Close is IRRELEVANT for mitigation checking.
1674+Mitigation is determined by whether price REACHED the zone, not where it closed.
1675+
1676+A candle that wicks into the OB zone but closes outside it → STILL MITIGATED.
1677+```
1678+
1679+#### 4.7.5 Tolerance for Mitigation
1680+
1681+```
1682+MITIGATION_TOLERANCE = 0.0001 (1 pip for forex)
1683+ = 1.0 (1 point for indices)
1684+
1685+Bullish OB is MITIGATED if:
1686+ Low[k] <= OB_TOP + MITIGATION_TOLERANCE
1687+
1688+Bearish OB is MITIGATED if:
1689+ High[k] >= OB_BOTTOM - MITIGATION_TOLERANCE
1690+
1691+This tolerance means: if price gets within 1 pip of the OB zone,
1692+it counts as mitigated (price effectively "tested" the zone).
1693+```
1694+
1695+#### 4.7.6 Equal Price (Exact Touch)
1696+
1697+```
1698+If Low[k] == OB_TOP exactly → MITIGATED (equal counts as touch)
1699+If High[k] == OB_BOTTOM exactly → MITIGATED (equal counts as touch)
1700+
1701+There is no special handling for exact equality.
1702+```
1703+

1771+
1772+```python
1773+def check_mitigation_status(ob, candles):
1774+ """
1775+ Determines if an Order Block has been mitigated.
1776+
1777+ Parameters:
1778+ ob: {
1779+ 'index': int, # Candle index where OB formed
1780+ 'type': str, # 'BULLISH' or 'BEARISH'
1781+ 'ob_top': float, # max(Open, Close) of OB candle
1782+ 'ob_bottom': float, # min(Open, Close) of OB candle
1783+ }
1784+ candles: full candle array
1785+
1786+ Returns:
1787+ {
1788+ 'mitigated': bool,
1789+ 'mitigated_at_index': int or None,
1790+ 'mitigation_type': 'FULL' | 'PARTIAL' | None
1791+ }
1792+ """
1793+ MITIGATION_TOLERANCE = 0.0001 # Configure per instrument
1794+
1795+ for k in range(ob['index'] + 1, len(candles)):
1796+
1797+ if ob['type'] == 'BULLISH':
1798+ # Check if price came DOWN to bullish OB
1799+ threshold = ob['ob_top'] + MITIGATION_TOLERANCE
1800+
1801+ if candles[k].Low <= threshold:
1802+ # Determine full vs partial
1803+ if candles[k].Low <= ob['ob_bottom']:
1804+ mitigation_type = 'FULL'
1805+ else:
1806+ mitigation_type = 'PARTIAL'
1807+
1808+ return {
1809+ 'mitigated': True,
1810+ 'mitigated_at_index': k,
1811+ 'mitigation_type': mitigation_type
1812+ }
1813+
1814+ elif ob['type'] == 'BEARISH':
1815+ # Check if price came UP to bearish OB
1816+ threshold = ob['ob_bottom'] - MITIGATION_TOLERANCE
1817+
1818+ if candles[k].High >= threshold:
1819+ # Determine full vs partial
1820+ if candles[k].High >= ob['ob_top']:
1821+ mitigation_type = 'FULL'
1822+ else:
1823+ mitigation_type = 'PARTIAL'
1824+
1825+ return {
1826+ 'mitigated': True,
1827+ 'mitigated_at_index': k,
1828+ 'mitigation_type': mitigation_type
1829+ }
1830+
1831+ # No mitigation found
1832+ return {
1833+ 'mitigated': False,
1834+ 'mitigated_at_index': None,
1835+ 'mitigation_type': None
1836+ }
1837+```

1839+### 4.10 Order Block Detection Algorithm – Complete
1840+
1841+```python
1842+def detect_order_blocks(candles, L=3, D=5, lookback=100):
1843+ """
1844+ Scans candle data for all three types of Order Blocks.
1845+
1846+ Parameters:
1847+ candles: array of candle objects
1848+ L: swing lookback (for structure break verification)
1849+ D: displacement window (candles after OB to confirm impulse)
1850+ lookback: how many candles back to scan
1851+
1852+ Returns:
1853+ list of Order Block objects
1854+ """
1855+ N = len(candles) - 1
1856+ start = max(0, N - lookback)
1857+ atr_period = 14
1858+ order_blocks = []
1859+
1860+ for i in range(start, N - D):
1861+
1862+ # Calculate ATR at this point
1863+ atr = calculate_atr(candles, i, atr_period)
1864+
1865+ # --- TYPE 1: Normal Order Block ---
1866+
1867+ # Check BULLISH Normal OB
1868+ if candles[i].Close < candles[i].Open: # Bearish candle
1869+ # Check for bullish displacement after
1870+ max_high_after = max(candles[k].High for k in range(i+1, min(i+D+1, N+1)))
1871+ bullish_move = max_high_after - candles[i].Low
1872+
1873+ if bullish_move >= 2 * atr:
1874+ # Check structure break
1875+ prev_sh = get_previous_swing_high(candles, i, L)
1876+ if prev_sh is not None and max_high_after > prev_sh:
1877+ order_blocks.append({
1878+ 'index': i,
1879+ 'type': 'BULLISH',
1880+ 'category': 'NORMAL',
1881+ 'ob_top': max(candles[i].Open, candles[i].Close),
1882+ 'ob_bottom': min(candles[i].Open, candles[i].Close),
1883+ 'ob_50': (candles[i].Open + candles[i].Close) / 2,
1884+ 'time': candles[i].Time
1885+ })
1886+
1887+ # Check BEARISH Normal OB
1888+ if candles[i].Close > candles[i].Open: # Bullish candle
1889+ min_low_after = min(candles[k].Low for k in range(i+1, min(i+D+1, N+1)))
1890+ bearish_move = candles[i].High - min_low_after
1891+
1892+ if bearish_move >= 2 * atr:
1893+ # Check structure break
1894+ prev_sl = get_previous_swing_low(candles, i, L)
1895+ if prev_sl is not None and min_low_after < prev_sl:
1896+ order_blocks.append({
1897+ 'index': i,
1898+ 'type': 'BEARISH',
1899+ 'category': 'NORMAL',
1900+ 'ob_top': max(candles[i].Open, candles[i].Close),
1901+ 'ob_bottom': min(candles[i].Open, candles[i].Close),
1902+ 'ob_50': (candles[i].Open + candles[i].Close) / 2,

1904+ })
1905+
1906+ # --- TYPE 2 & 3 detection (Mitigation Blocks & Breaker Blocks) ---
1907+ # These require existing Normal OBs to be identified first
1908+

1910+ mitigation_blocks = detect_mitigation_blocks(candles, start, N, D, atr_period)

1921+
1922+```python
1923+def detect_breaker_blocks(candles, existing_obs):
1924+ """
1925+ Identifies Breaker Blocks from failed Normal Order Blocks.
1926+
1927+ A Breaker Block forms when:
1928+ 1. An existing OB gets its zone FULLY VIOLATED (price breaks through entirely)
1929+ 2. Market structure shifts in the opposite direction
1930+ 3. The failed OB zone can now be used as support/resistance in the new direction
1931+
1932+ Parameters:
1933+ candles: full candle array
1934+ existing_obs: list of previously identified Normal Order Blocks
1935+
1936+ Returns:
1937+ list of Breaker Block objects
1938+ """
1939+ breaker_blocks = []
1940+
1941+ for ob in existing_obs:
1942+ i = ob['index']
1943+
1944+ if ob['type'] == 'BEARISH':
1945+ # Bearish OB that FAILS → becomes Bullish Breaker
1946+ # Failure = price breaks ABOVE OB_TOP
1947+
1948+ for k in range(i + 1, len(candles)):
1949+ if candles[k].High > ob['ob_top']:
1950+ # OB has failed - price broke above resistance
1951+
1952+ # Verify structure shift: new higher high after the break
1953+ # Check if a swing high forms above OB_TOP within next 10 candles
1954+ structure_shifted = False
1955+ for m in range(k, min(k + 10, len(candles))):
1956+ if candles[m].High > ob['ob_top']:
1957+ structure_shifted = True
1958+ break
1959+
1960+ if structure_shifted:
1961+ breaker_blocks.append({
1962+ 'index': i, # Same candle as original OB
1963+ 'type': 'BULLISH', # FLIPPED direction
1964+ 'category': 'BREAKER',
1965+ 'ob_top': ob['ob_top'],
1966+ 'ob_bottom': ob['ob_bottom'],
1967+ 'ob_50': ob['ob_50'],
1968+ 'time': ob['time'],
1969+ 'failed_at_index': k,
1970+ 'original_type': 'BEARISH'
1971+ })
1972+ break # Only first failure matters
1973+
1974+ elif ob['type'] == 'BULLISH':
1975+ # Bullish OB that FAILS → becomes Bearish Breaker
1976+ # Failure = price breaks BELOW OB_BOTTOM
1977+
1978+ for k in range(i + 1, len(candles)):
1979+ if candles[k].Low < ob['ob_bottom']:
1980+ # OB has failed
1981+
1982+ structure_shifted = False
1983+ for m in range(k, min(k + 10, len(candles))):
1984+ if candles[m].Low < ob['ob_bottom']:
1985+ structure_shifted = True
1986+ break
1987+
1988+ if structure_shifted:
1989+ breaker_blocks.append({
1990+ 'index': i,
1991+ 'type': 'BEARISH', # FLIPPED direction
1992+ 'category': 'BREAKER',
1993+ 'ob_top': ob['ob_top'],
1994+ 'ob_bottom': ob['ob_bottom'],
1995+ 'ob_50': ob['ob_50'],
1996+ 'time': ob['time'],
1997+ 'failed_at_index': k,
1998+ 'original_type': 'BULLISH'
1999+ })
2000+ break
2001+

2003+```

2026+

2031+ If candles[k-1].Low > OB_TOP AND candles[k].Low < OB_BOTTOM:

2041+ If candles[k-1].Low > OB_TOP AND candles[k].Low <= OB_TOP:

2070+## SECTION 5: ORDER BLOCK FILTERING ALGORITHM
2071+
2072+### 5.1 Overview
2073+
2074+Not all detected Order Blocks are tradeable. The bot must apply a **multi-stage filter** to eliminate invalid OBs and retain only those that satisfy ALL conditions simultaneously.
2075+
2076+**An Order Block is VALID for trading if and only if it passes ALL of the following filters:**
2077+
2078+```
2079+FILTER 1: Located inside Premium or Discount zone (correct zone for its type)
2080+FILTER 2: Unmitigated (never been revisited since formation)
2081+FILTER 3: Inside the selected dealing range (between the active swing pair)
2082+FILTER 4: Valid according to swing logic (swing pair passes 50% rule)
2083+```
2084+
2085+**ALL four filters must pass. If ANY single filter fails → REJECT the Order Block.**
2086+
2087+### 5.2 Filter Execution Order (Optimized)
2088+
2089+Filters should be applied in order of **computational cheapness** and **highest rejection rate** first:
2090+
2091+```
2092+PRIORITY ORDER (execute in this sequence):
2093+
2094+ STEP 1: SWING VALIDITY CHECK (Filter 4)
2095+ - Cheapest: single boolean check on cached swing state
2096+ - Highest rejection rate: if swing is invalid, ALL OBs are rejected at once
2097+ - Cost: O(1) — already computed in monitoring loop
2098+
2099+ STEP 2: DEALING RANGE MEMBERSHIP (Filter 3)
2100+ - Simple price comparison
2101+ - Cost: O(1) per OB
2102+
2103+ STEP 3: ZONE ALIGNMENT (Filter 1)
2104+ - Price comparison against equilibrium
2105+ - Cost: O(1) per OB
2106+
2107+ STEP 4: MITIGATION STATUS (Filter 2)
2108+ - Most expensive: requires scanning all candles after OB formation
2109+ - Cost: O(N) per OB where N = candles since OB formed
2110+ - Applied LAST to minimize unnecessary scans
2111+```
2112+
2113+**Rationale:** If the swing pair is invalid (Step 1), we skip ALL subsequent checks for ALL OBs, saving significant computation.
2114+
2115+### 5.3 Filter 1: Zone Alignment – Detailed Rules
2116+
2117+```
2118+INPUT:
2119+ - OB object: {type, ob_top, ob_bottom, ob_50}
2120+ - Fibonacci data: {equilibrium, swing_high, swing_low}
2121+
2122+RULE:
2123+ IF ob.type == 'BULLISH':
2124+ PASS if ob.ob_50 < equilibrium (OB midpoint is in DISCOUNT)
2125+ FAIL if ob.ob_50 >= equilibrium (OB is in premium/equilibrium)
2126+
2127+ IF ob.type == 'BEARISH':
2128+ PASS if ob.ob_50 > equilibrium (OB midpoint is in PREMIUM)
2129+ FAIL if ob.ob_50 <= equilibrium (OB is in discount/equilibrium)
2130+
2131+NOTE: The OB's MIDPOINT (ob_50) determines its zone, not the full range.
2132+This prevents edge cases where an OB straddles the equilibrium line.
2133+```
2134+
2135+**Edge Case: OB straddles equilibrium**
2136+```
2137+If ob_bottom < equilibrium < ob_top:
2138+ Use ob_50 (midpoint) to determine zone.
2139+
2140+ Example:
2141+ OB_TOP = 1.0110, OB_BOTTOM = 1.0090, Equilibrium = 1.0100
2142+ OB_50 = (1.0110 + 1.0090) / 2 = 1.0100
2143+
2144+ OB_50 == Equilibrium → Treat as ON equilibrium → REJECT
2145+
2146+ Tolerance: if |ob_50 - equilibrium| <= 0.0002 → REJECT (too close to equilibrium)
2147+```
2148+
2149+
2150+
2151+### 5.4 Filter 2: Unmitigated Status – Detailed Rules
2152+
2153+```
2154+INPUT:
2155+ - OB object with formation index
2156+ - All candles from formation to present
2157+
2158+RULE:
2159+ Call check_mitigation_status(ob, candles) from Section 4.9
2160+
2161+ PASS if result.mitigated == False
2162+ FAIL if result.mitigated == True
2163+
2164+This is a binary check — either the OB has been touched or it hasn't.
2165+No partial passes. One touch = mitigated = rejected.
2166+```
2167+
2168+### 5.5 Filter 3: Dealing Range Membership – Detailed Rules
2169+
2170+```
2171+INPUT:
2172+ - OB object: {ob_top, ob_bottom}
2173+ - Active dealing range: {swing_high_price, swing_low_price}
2174+
2175+RULE:
2176+ The OB must be ENTIRELY within the dealing range.
2177+
2178+ PASS if:
2179+ ob_top <= swing_high_price AND ob_bottom >= swing_low_price
2180+
2181+ FAIL if:
2182+ ob_top > swing_high_price OR ob_bottom < swing_low_price
2183+
2184+This ensures the OB is not from a different/older price structure
2185+that extends beyond the current dealing range.
2186+```
2187+
2188+**Edge Case: OB exactly at swing boundary**
2189+```
2190+If ob_top == swing_high_price → PASS (exactly at boundary is acceptable)
2191+If ob_bottom == swing_low_price → PASS (exactly at boundary is acceptable)
2192+```
2193+
2194+### 5.6 Filter 4: Swing Validity – Detailed Rules
2195+
2196+```
2197+INPUT:
2198+ - Active swing pair validity status (from Section 3 monitoring)
2199+
2200+RULE:
2201+ PASS if active_swing_pair.valid == True
2202+ FAIL if active_swing_pair.valid == False (50% has been touched)
2203+
2204+When this fails:
2205+ - ALL order blocks associated with this swing pair are REJECTED simultaneously
2206+ - Bot must find a new valid swing pair before any OBs can be accepted
2207+```

2280+### 5.8 Priority When Multiple Valid OBs Exist
2281+
2282+If multiple Order Blocks pass all filters, the bot must select the BEST one:
2283+
2284+```
2285+PRIORITY RANKING (highest to lowest):
2286+
2287+1. CLOSEST TO CURRENT PRICE (most likely to be reached first)
2288+ For Bullish OBs: highest OB_TOP (closest to price coming down)
2289+ For Bearish OBs: lowest OB_BOTTOM (closest to price coming up)
2290+
2291+2. IN KEY FIBONACCI ZONE (50%-61.8% area preferred)
2292+ OBs within the key sub-zone get priority over those in outer zones.
2293+
2294+ Score calculation:
2295+ For Bullish OB:
2296+ key_lower = fib_data['zones']['discount']['key_zone_lower'] # 38.2% from low
2297+ key_upper = fib_data['zones']['discount']['key_zone_upper'] # 50% from low
2298+
2299+ if key_lower <= ob['ob_50'] <= key_upper:
2300+ zone_score = 10 # In key zone
2301+ else:
2302+ zone_score = 5 # In discount but not key zone
2303+
2304+ For Bearish OB:
2305+ key_lower = fib_data['zones']['premium']['key_zone_lower'] # 50%
2306+ key_upper = fib_data['zones']['premium']['key_zone_upper'] # 61.8% from low
2307+
2308+ if key_lower <= ob['ob_50'] <= key_upper:
2309+ zone_score = 10
2310+ else:
2311+ zone_score = 5
2312+
2313+3. ORDER BLOCK TYPE PRIORITY
2314+ Normal OB → priority_score = 3 (highest confidence)
2315+ Breaker Block → priority_score = 2
2316+ Mitigation Block → priority_score = 1 (lowest confidence)
2317+
2318+4. MOST RECENT FORMATION
2319+ If all else is equal, prefer the OB that formed most recently.
2320+ More recent = more relevant institutional activity.
2321+```
2322+
2323+**Composite Scoring:**
2324+```python
2325+def score_order_block(ob, fib_data, current_price):
2326+ """Calculate priority score for OB ranking."""
2327+
2328+ # Distance score (closer to price = better, normalized 0-10)
2329+ if ob['type'] == 'BULLISH':
2330+ distance = current_price - ob['ob_top']
2331+ else:
2332+ distance = ob['ob_bottom'] - current_price
2333+
2334+ # Negative distance means price hasn't reached OB yet (good)
2335+ # Smaller positive distance = closer = higher priority
2336+ distance_score = max(0, 10 - (distance * 10000)) # Scale for forex
2337+
2338+ # Zone score
2339+ zone_score = calculate_zone_score(ob, fib_data) # 5 or 10
2340+
2341+ # Type score
2342+ type_scores = {'NORMAL': 3, 'BREAKER': 2, 'MITIGATION': 1}
2343+ type_score = type_scores.get(ob['category'], 1)
2344+
2345+ # Recency score (normalize by index)
2346+ recency_score = ob['index'] / 100 # Higher index = more recent = better
2347+
2348+ # Composite
2349+ total_score = (zone_score * 3) + (distance_score * 2) + (type_score * 2) + recency_score
2350+
2351+ return total_score
2352+```

2487+

2489+ active_unmitigated_obs = [] # Currently valid, being monitored
2490+ mitigated_obs = [] # Consumed, archived for logging only
2491+ rejected_obs = [] # Failed zone/range check

2497+ - If mitigated, move to mitigated_obs list
2498+
2499+5. On new swing pair detected:
2500+ - Recalculate equilibrium

2502+ - Rebuild active_unmitigated_obs list
2503+```

2941+### 6.13 STAGE 11: Execute Entry + Set Stop Loss – Detailed
2942+
2943+**Trigger:** Trade signal confirmed in Stage 10.
2944+
2945+**Process:**
2946+```
2947+1. CALCULATE STOP LOSS (ADR-based):
2948+
2949+ a. Get previous 5 TRADING DAYS of daily candle data
2950+ (exclude weekends/holidays — only days where market was open)
2951+
2952+ b. Calculate each day's range using WICKS (not body):
2953+ Day_Range[d] = Daily_High[d] - Daily_Low[d]
2954+
2955+ c. Calculate ADR:
2956+ ADR = (Day_Range[1] + Day_Range[2] + Day_Range[3] + Day_Range[4] + Day_Range[5]) / 5
2957+
2958+ d. Calculate Stop Loss distance:
2959+ SL_DISTANCE = ADR / 2
2960+
2961+ e. Set Stop Loss price:
2962+ For BUY trade: SL_PRICE = ENTRY_PRICE - SL_DISTANCE
2963+ For SELL trade: SL_PRICE = ENTRY_PRICE + SL_DISTANCE
2964+
2965+2. EXECUTE ORDER:
2966+ {
2967+ type: 'BUY_LIMIT' | 'SELL_LIMIT' (or MARKET if price already at level),
2968+ entry_price: OB_50,
2969+ stop_loss: SL_PRICE,
2970+ lot_size: calculated_from_risk_management,
2971+ magic_number: unique_trade_id,
2972+ comment: "0GMT_HTF_OB_{timeframe}_{ob_category}"
2973+ }
2974+
2975+3. LOG TRADE:
2976+ Record all details for post-analysis.
2977+```

2979+**ADR Calculation – Numerical Example:**
2980+```
2981+Previous 5 trading days:
2982+ Day 1 (Mon): High=1.0350, Low=1.0300 → Range = 0.0050 (50 pips)
2983+ Day 2 (Tue): High=1.0320, Low=1.0280 → Range = 0.0040 (40 pips)
2984+ Day 3 (Wed): High=1.0310, Low=1.0265 → Range = 0.0045 (45 pips)
2985+ Day 4 (Thu): High=1.0340, Low=1.0295 → Range = 0.0045 (45 pips)
2986+ Day 5 (Fri): High=1.0360, Low=1.0320 → Range = 0.0040 (40 pips)
2987+
2988+Total Range = 50 + 40 + 45 + 45 + 40 = 220 pips
2989+ADR = 220 / 5 = 44 pips = 0.0044
2990+SL_DISTANCE = 44 / 2 = 22 pips = 0.0022
2991+
2992+If ENTRY (BUY) at 1.0100:
2993+ SL = 1.0100 - 0.0022 = 1.0078
2994+
2995+If ENTRY (SELL) at 1.0150:
2996+ SL = 1.0150 + 0.0022 = 1.0172
2997+```
